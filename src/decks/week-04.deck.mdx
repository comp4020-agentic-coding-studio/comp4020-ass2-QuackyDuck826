# Sensors

Turning light, distance, motion or force into a number your code can use

---

## Recap

- physical computing opens with **input**: a microcontroller reading the
  world, not writing to it yet
- "reading a sensor" is a loop, not a one-off event — the board checks
  again and again
- a walkthrough of two or three common sensor types, and where each is a
  good fit
- today's crit looks at Studio Brief 1 — a digitizing technique combined
  with Programming I

---

## Wiring a sensor

An analog pin is for a continuously varying signal — light or
distance — where the value can sit anywhere across a range. A digital
pin is for something that's simply on or off, like a button or some
motion sensors. The pin type you choose has to match what the sensor
actually produces.

---

## Reading the raw value

Read the pin in a loop, and print whatever comes back before you do
anything else with it. A value you can see on screen is a value you
can trust — one you can't see is a guess.

```cpp
int raw = analogRead(A0);
Serial.println(raw);
```

---

## Scaling it to what you need

The raw range a pin reports rarely matches the range something else
wants, so scale it with `map()`.

```cpp
int brightness = map(raw, 0, 1023, 0, 255);
```

Only build anything else on top once that printed, scaled number moves
the way you'd expect when you wave a hand or change the light.
